# Admin Panel

Панель владельца фонда Free Mine: управление сменами OreVein, капиталом, операциями и преемниками. Интерфейс на SolidJS, бекенд — `ghcr.io/free-mine/admin-server` (совместим с `admin-server@ea9f271`).

## Запуск

Требуется Docker Compose. Создайте `.env` на основе `.env.example`:

| Переменная          | Назначение                                                                                                                                                                   |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RPC_URL`           | RPC Avalanche C-Chain для расчётов и исполнения операций.                                                                                                                    |
| `PUBLIC_SERVER_URL` | Обязательный HTTP(S)-адрес основного сервера. Допустим префикс пути; `/v1` добавляется автоматически. Логин, пароль, query и fragment недопустимы.                           |
| `PUBLIC_SERVER_KEY` | API-ключ для синхронизации журнала и обновления снимка. Создаётся в репозитории `server`: `docker compose exec server node dist/cli/key.js`. Для публичного чтения не нужен. |
| `PRIVATE_KEY`       | Ключ текущего владельца OreVein для выполнения операций. Без подходящего ключа доступно только чтение и проверка планов.                                                     |

Ключи и RPC URL остаются на бекенде. Для основного сервера на хосте Docker Desktop используйте `host.docker.internal` вместо `localhost`.

```sh
docker compose pull backend
docker compose up --build -d
```

Откройте <http://localhost:5175> или <http://127.0.0.1:5175>. Панель доступна только на локальном интерфейсе; nginx проксирует REST и WebSocket на `backend:3000`. Для WebSocket используется `localhost`; nginx также преобразует Origin с `127.0.0.1` и `[::1]` в `localhost`, сохраняя схему и порт. Остальные Origin проверяет бекенд.

При обновлении старого `.env` добавьте `PUBLIC_SERVER_URL` и `PUBLIC_SERVER_KEY`. Переменные `PORT`, `DATA_DIR` и `ALLOWED_ORIGINS` больше не используются: порт бекенда — `3000`, каталог данных — `/app/data`. Для Compose оставьте `HOST` по умолчанию (`0.0.0.0`).

## Данные и восстановление

Публичный снимок и постоянный журнал хранятся на основном сервере. Локальные незавершённые и ещё не синхронизированные операции сохраняются в `/app/data/operations.pending.json` в volume `backend-data`. Сохраняйте volume при обновлении: `docker compose down --volumes` удаляет его вместе с ещё не переданными записями; обычные `stop`, `restart` и `down` сохраняют. При переходе со старого контейнера перенесите его журнал из `/app/data` в volume.

При недоступности основного сервера исполнение через RPC продолжается, а `/v1/state` возвращает последний доступный публичный снимок. Разделы панели читают данные через RPC. Готовность `/ready` не гарантирует синхронизацию журнала: раздел «Операции» показывает состояние `/v1/sync`, включая неполную историю, потерю связи и несохранённые записи. В режиме только чтения журнал не изменяется.

Перед отправкой панель сохраняет `previewId` и `requestId` в браузере. При потере ответа «Проверить отправку» повторяет ту же пару, в том числе после перезагрузки страницы. До выяснения результата новая операция недоступна. Неподтверждённые планы хранятся в памяти бекенда: после его перезапуска, истечения срока или изменения плана нужны новый просмотр и подтверждение. Закрытие страницы не отменяет поставленную в очередь операцию.

## Возможности

- **Фонд:** смены и заявки, финансирование и закрытие, цена входа, расчётный токен и URI контракта.
- **Капитал:** балансы OreVein и газ владельца; внесение, вывод, заём и погашение Aave; обмен LFJ; создание и обслуживание позиций Uniswap.
- **Операции:** предварительный план и подтверждение, очередь, шаги, receipts и фактический газ. Для `needs_attention` — проверка подтверждённой внешней замены.
- **Преемники:** назначение, перенос даты и удаление. Время вводится и отображается в МСК (UTC+3).

Для создания позиции Uniswap нужны положительные суммы обоих активов и расстояние до каждой границы: больше 0 и меньше 100%, до 6 знаков после точки. Сервер подбирает диапазон с использованием не менее 99% каждого актива; границы могут быть несимметричными. Цены указаны в токене B за 1 A; для нового пула нужна начальная цена. План показывает ожидаемые суммы внесения и остатки.

Суммы передаются десятичными строками и рассчитываются через `BigInt`. Балансы и суммы капитала показываются с точностью до 8 знаков без округления; кнопка копирования сохраняет полную сумму. При ошибках остаётся последний успешный снимок с датой, при потере готовности новые записи блокируются. WebSocket восстанавливается автоматически, REST обновляется каждые 15 секунд.

## Разработка и проверки

Требуется Node.js 24.13.1–24.x. Vite на <http://localhost:5173> проксирует API через Compose на порт 5175.

```sh
npm ci
npm run dev
```

```sh
npm run build
npm run lint
npm test
```

Playwright использует изолированный API и автоматически запускает Vite; ключи, RPC и работающий бекенд не нужны. На Windows используется установленный Edge, на других системах установите Chromium: `npx playwright install chromium`. Браузер переопределяется через `PLAYWRIGHT_CHANNEL`. Артефакты находятся в `.tmp/`. Реальные транзакции проверяются отдельно с настроенным бекендом.

GitHub Actions выполняет те же проверки на pull request. Отчёт с трассировками упавших тестов доступен в артефакте `playwright-report` в течение 7 дней: после распаковки откройте его командой `npx playwright show-report <папка-отчёта>`.
